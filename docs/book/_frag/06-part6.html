29  求根器链与数值稳定性

29.1 本章解决什么问题

综合链里所有求根（E 多项式、分母、谱密度 R）都走同一条 AdaptiveRootSolver 链。本章给三级求根器的算法、门限、 为何不用 nalgebra 伴随矩阵、以及高阶稳定性边界。

29.2 AdaptiveRootSolver 链

AdaptiveRootSolver（approx/complex_poly.rs:805-823， impl :816-842）按顺序尝试，成功即返回，失败 fall-through：

  1. FaerRootSolver（faer 复伴随矩阵特征值，首选）；
  2. DurandKernerRootSolver（迭代法，fallback）；
  3. AberthRootSolver（last resort）。

关键实现事实（:56-72 文档）：CompanionMatrixRootSolver （nalgebra Schur）故意不在链中——其复系数 2n×2n 实嵌入分支会返回 共轭翻转的伪根（有专门回归测试钉死）。它只保留为实系数测试 oracle。 不是"DK 优先"——是 faer 优先（旧文档曾误述）。

29.3 FaerRootSolver（伴随矩阵 + 平衡 + 后向残差门）

FaerRootSolver（complex_poly.rs:660-810）：

  1. monic 归一（:679-684）；
  2. 建复伴随矩阵：次对角 1、末列 −c_k（:686-695）；
  3. Parlett–Reinsch 对角相似平衡（:704-742）：至多 degree 次 sweep； 每步 W ← D·W·D⁻¹，d_i = sqrt(col_norm/row_norm) 钳到 [1e-100, 1e100]，当 row_norm < 0.5·col_norm || col_norm < 0.5·row_norm 时应用； row_norm ≤ 1e-300 || col_norm ≤ 1e-300 跳过。 平衡改善特征值条件数（高阶关键）；
  4. balanced.eigenvalues::<c64>()（:744）；
  5. 后向残差门（:778-786）：max_backward_residual(&normalized, &roots)， 接受当 !roots_contain_non_finite(roots) && max_backward ≤ FAER_BACKWARD_RESIDUAL_TOL (= 1e-3) （:867）。拒绝 → NumericalFailure，让链 fall-through。 后向残差 = |p(r)| / Σ_k |c_k|·|r|^k（尺度无关，scale.max(1e-300)， max_backward_residual :880-901）。

为什么有后向残差门：病态伴随矩阵的特征值可能是"伪根"（后向残差大）。 门把它变成 typed 失败 + fall-through，而非静默出货垃圾特征值。

29.4 DurandKerner 与 Aberth

DurandKerner（:266-360）：monic 归一（拒 leading.norm_sqr() ≤ 1e-24）； Cauchy 半径 1 + max_k |c_k|；黄金角初始化 （golden_angle = 2.399_963_229_728_653 = 2π/φ²，:304）； max_iterations = (128 + (degree−10)·4).min(512)；convergence_tol = 1e-13； DK 更新 delta = p(root)/Π(root−root_j)（denom.norm_sqr() ≤ 1e-30 跳过）； 收敛 max_delta ≤ 1e-13 && 无非有限；残差 fallback max_residual < 1e-8（:353）；否则 NumericalFailure。

Aberth-Ehrlich（:374-490）：同初始化；max_iterations = (200+(degree−10)·6).min(800) （比 DK 多）；Newton 修正 w = p(z)/p′(z) + Aberth 和 Σ 1/(z_k−z_j)， delta = w/(1 − w·aberth_sum)（分母近零退回纯 Newton）；同 1e-8 残差 fallback。

29.5 数值稳定性：为什么 faer 优先

复多项式求根本质病态（根对系数扰动敏感）。三级链的稳定性排序：

  • faer 伴随 + 平衡：特征值方法，Parlett–Reinsch 平衡直接改善条件数， 对高阶（N≥20）最稳；后向残差门兜住病态情况；
  • Durand-Kerner：O(N²) 迭代，精度退化 O(N²εmach)（这就是第 12 章 自适应极点容差 1e-6·(N/5)² 的由来）；
  • Aberth：带 Newton 修正，局部收敛快，作 last resort。

实现事实：benches/root_solvers.rs 对 4 个求根器 （DurandKerner、Aberth、CompanionMatrix、Faer）在 degree 10/20/30 测残差， examples/solver_accuracy_comparison.rs 做 orders 4–40 的残差对照—— 实测 faer 在高阶残差最小（这是 faer 优先的实测依据）。

29.6 高阶稳定性边界

实现事实（README + examples/high_order_stability.rs）： 无耗全极点验证稳定到阶 28、有限传输零点稳定到阶 24（RL 20–22 dB）， 经自适应极点轴容差。阶 30+ 可能被 typed NumericalFailure 拒绝 （极点实部超 1e-6·(N/5)² 容差）——边界是设计相关的（零点布局影响）。 high_order_stability 示例（orders 10–40）给出验证边界 + 可复现的拒绝。

不要扩大声明 "高阶稳定到 28/24"是已验证参数范围（全极点/有限零点、RL 20–22）， 不是对所有输入的保证。阶 30+ 拒绝是 typed 行为（有边界文档），不是静默错。

29.7 本章小结

求根 = faer 伴随+Parlett–Reinsch 平衡+后向残差门(1e-3) → Durand-Kerner(1e-13, 残差 1e-8) → Aberth(更多迭代) 三级 fall-through 链。nalgebra 伴随意外的伪根被排除在链外。 高阶稳定到 28(全极点)/24(有限零点)，30+ 可能 typed 拒绝（设计相关）。 下一章容差、尺度、聚类与病态。

30.3 尺度原则

阈值设计遵循三条尺度原则：

  1. 相对优先：凡涉及"大小比较"的阈值尽量相对（1e-10·‖·‖、 1e-12·max(1,|a|,|b|)），只对绝对量（如极点实轴噪声、dB 地板）用绝对值；
  2. 分离噪声与信号：阈值设在"求根/旋转噪声量级"（~1e-10..1e-13）与 "物理量量级"（~1e-3..O(1)）之间的空隙；空隙不够时（如重根 1e-5 vs 极点间距 1.6e-3） 用单链聚类 + 均值/簇大小而非重推系数（病态）；
  3. 随阶数自适应：精度退化 O(N²ε) 的地方（极点轴容差）显式乘 (N/5)²， 不固定 1e-6（否则高阶误拒）。

30.4 病态输入的处理策略

  • 病态伴随矩阵（求根）→ faer 后向残差门 fall-through 到迭代法；
  • 重根 → 单链聚类 + Laurent 主部（横向链拒绝 m≥2，[§12.2](#sec122)）；
  • 近奇异 Schur（快路径）→ 该点 typed 失败 → 落回 LU（[§20.3](#sec203)）；
  • 病态 LM 步（优化）→ 扰动失败步长减半≤4（[§28.4](#sec284)）；
  • 全有限 ε≤1 → typed PreconditionViolation（[§8.4](#sec84)）；
  • 非有限值 → 门自动失败（[§21.3](#sec213)）/ 求根门拒绝。

共同点：病态不是静默产出近似答案，而是 typed 失败 / 回退 / 显式拒绝。 这是库的核心错误策略（[§31](#ch31)）。

30.5 本章小结

阈值分六类（求根门、聚类、极点/残差分类、矩阵小值、对称、退化地板）， 遵循"相对优先、分离噪声与信号、随阶数自适应"三原则。病态一律走 typed 失败/回退/拒绝， 不静默近似。下一章支持边界与 typed error 体系。

31.4 诊断信息与处理方向

每个 typed error 的 Display 消息带具体值与替代建议：

  • 全有限 ε≤1 → 消息含实际 ε 值 + "改用混合零点（至少保留一个 ∞）"；
  • 通带零点 → 消息指明 |z| 值与 Feldtkeller 原因；
  • 阶 30+ 拒绝 → 消息含极点实部与容差（指向设计相关边界）；
  • 多频带 K≥3 → 消息明说"需复根(Zolotarev)/多函数特征"。
处理原则 库不自动建议改设计目标来掩盖失败。拒绝消息给"为什么不行 + 什么配置可行"， 但不擅自放宽规格。用户据此调整（如改混合零点、降阶、放宽 RL），而非库静默妥协。

31.5 与验证的关系

typed error 是构造/算法期的拒绝；verify_against_spec （[§32](#ch32)）是响应期的规格检查（返回 pass/fail/skipped，不抛错）。 两者互补：前者保证"能综合"，后者保证"综合出的响应满足规格"。 synthesize() 成功不等于规格满足（[§1.6](#sec16)）。

31.6 本章小结

8 个 typed error 变体覆盖全部失败；支持边界明确（高阶 30+ 设计相关拒绝、 通带零点/横向重根/K≥3/全有限ε≤1 各 typed 拒绝）。诊断消息带值与替代建议， 不自动放宽规格。下一章规格验证、独立基准与回归测试。

32  规格验证、独立基准与回归测试

32.1 本章解决什么问题

综合成功后，如何独立验证响应满足规格？MFS 提供三层： verify_against_spec（绝对规格门）、文献锚定基准 （Cameron 1999/2011 公开矩阵/响应）、回归测试（历史失败配置）。 本章给验证 API、独立基准门、回归与 property 测试，以及测试分层。

32.2 verify_against_spec（绝对规格门）

crate::verify::verify_against_spec（design.rs:163-165 引用） 对评估后的响应检查绝对规格：回波损耗 RL、插入损耗、零点深度、带外衰减窗。 关键语义（design.rs:161-166 文档）：synthesize() 成功 不保证响应满足 RL 规格——verify_against_spec 对收紧或不可行规格 返回 Fail/Skipped 而非静默通过。这是"合成 ≠ 规格满足"的落地。

32.3 独立基准（文献锚定）

tests/benchmark_standard.rs（868 行）是跨语言一致性 + 文献锚定的核心：

  • 锚定验证：Cameron 印刷的横向+折叠矩阵喂进 mfs 响应引擎， 断言折叠前后响应不变（ANCHOR_TOL = 1e-10）； 印刷对一致（ANCHOR_PRINTED_PAIR_TOL = 2e-3，4 位小数印刷量子）；
  • 覆盖：6 个标准二端口案例（twoport_4_4、6_3、 4_2_unity、6_2_culdesac、8_3、7_1_2）， 强制 folded_response_invariance 从标准读规格（非手抄）；
  • 漂移守卫：vendored 数据 byte-for-byte 对 ../filter-bench/data/ + SHA-256 对 MANIFEST.sha256（双层）；
  • 支持模块自检：SHA-256 对 NIST FIPS 180-4 向量、流式 vs 一次性、 折叠掩模（tol 0.0）、mfs 综合折叠矩阵复现印刷书矩阵 （coupling_abs 门 <0.02，含 N=8 带边）、 跨后端等价对 Python 参考（特征值偏差 1e-6）。

四道契约门：response_invariance(1e-10)、folded_mask(0.0)、 coupling_abs(0.02)、cross_backend_equivalence(1e-6)。

文献 fixture 清单（docs/literature-fixture-catalog.md）： cameron_generalized_order4_spec、cameron_style_section_polynomials、 literature_reference_grid、cameron_single_zero_exact_case（精确一阶递推锚）、 cameron_order3_generalized_pipeline_exact_case（精确 order-3 全 helper 锚）。 边界：fixture 是"文献支撑的工作流锚 + 两个精确低阶数值锚"， 不应解读为"精确复现公开耦合表"（更强的声明需 source-to-output 可追溯，见附录 F）。

32.7 本章小结

验证三层：verify_against_spec（绝对规格，Fail/Skipped 非静默）、 文献锚定基准（1e-10 不变性、0.02 耦合、1e-6 跨后端）、回归(11)+property(10)。 测试分五层（单元/property/回归/集成/fixture）。"合成 ≠ 规格满足"由 verify 落地。 下一章工程使用（Rust/Python/CLI）。

33  Rust、Python 与 CLI 的使用流程

33.1 本章解决什么问题

把前五篇的算法通过三种接口暴露给使用者：Rust API（主）、 Python 绑定（可选 feature）、JSON 驱动 CLI。 本章给各接口的使用流程与差异，强调"接口包装 vs 数学算法"的分离 （CLI/Python/JSON 是接口，不是核心数学，故放在本篇而非第二篇）。

33.2 Rust API（主接口）

入口 FilterDesign（[§1.6](#sec16)）。典型流程：

use mfs::prelude::*;

// 带通设计（物理频率）
let design = FilterDesign::bandpass(6, 23.0, 6.75e9, 300e6)
    .zeros_hz([6.4e9, 6.5e9, 7.0e9])
    .unloaded_q(3000.0)        // 可选 Q
    .synthesize()?;

// 拓扑变换
let folded  = design.to_folded()?;   // 折叠
let arrow   = design.to_arrow()?;    // 箭头
let ct      = design.to_ct(&[1.8082])?; // 级联三节（主零点）
let cq      = design.to_cq(&[(a,b)])?;  // 级联四节（零点对）

// 响应（自动快路径 + LU 回退，[§21](#ch21)）
let response = design.response(6.0e9, 7.5e9, 501)?;
for s in &response.samples {
    // s.frequency_hz, s.s21_db(), s.s11_db(),
    // s.s21_phase_deg(), s.group_delay (Option, 归一化单位)
}

// 去归一化（物理 Hz + 外部 Q）
let scaled = design.scale()?;

// Touchstone 导出 / 活动网络 / 级联
design.save_touchstone("filter.s2p")?;
let network  = design.build_network()?;
let cascaded = design.cascade(&other_design)?;

// 规格验证（[§32.2](#sec322)）
// verify_against_spec(&response, &spec)?;

归一化原型：FilterDesign::prototype(4, 20.0).zeros([-1.5,1.5]).synthesize() + response_normalized(-3.0, 3.0, 201)。 带边入口：bandpass_edges(order, rl, f_start, f_stop)（几何均值中心）。 低层控制：MatrixSynthesisEngine::synthesize(&polynomials)、 synthesize_residue_expansions、classify_residues（[§10–12](#ch10)）。

33.3 Python 绑定

可选 feature（python，pyo3 0.23，extension-module）。 需 Rust ≥ 1.86 + 匹配 ABI 的 Python。

# 构建
pip install maturin
maturin develop --features python

# 使用
import mfs
design = mfs.bandpass(order=6, rl=23.0, center=6.75e9, bw=300e6,
                      zeros=[6.4e9, 6.5e9, 7.0e9])
freq, s21, s11 = design.response(6.0e9, 7.5e9, 501)
m = design.folded()              # 耦合矩阵为 2D list
design.save_touchstone("filter.s2p")
design.save_touchstone("f.s2p", freq_unit="MHz", format="DB")

实现事实：src/python.rs（30.6KB）是接口包装—— 把 Rust FilterDesign 方法暴露为 Python 方法，不重复任何数学。 Python 路径的响应/矩阵与 Rust 路径逐位一致（同一 FilterDesign）。

33.4 JSON 驱动 CLI

src/bin/mfs_cli/（feature cli，clap 4）。 pipeline/ 模块实现分阶段编排：

mfs_cli --input request.json --format json --stage matrix_synthesis
mfs_cli --input request.json --resume context.json   # 增量恢复

Stage 管道（pipeline/stages.rs，4 个具体 stage）：

  1. ApproximationStage：FilterSpec → PolynomialSet；
  2. MatrixSynthesisStage：PolynomialSet → CouplingMatrix；
  3. TopologyTransformStage：CouplingMatrix → TransformOutcome；
  4. ResponseEvaluationStage：CouplingMatrix + Grid(+Mapping) → SParameterResponse。

run_full_pipeline(request)（一次全跑）、run_stage（增量单 stage）、 save_context/load_context（JSON 持久化恢复）、 describe_schema()（JSON Schema）。 频率映射：request 带 mapping（bandpass/lowpass）则经 MappingConfig::build_mapping 评估物理 Hz 网格；否则网格视为已归一化。 未知/不完整 mapping → InvalidFrequency（不再静默忽略，历史修正）。

CLI 子命令：design、io、multiplexer、target、 optimize（调谐/提取，[§28](#ch28)）。 tests/cli_integration.rs（551 行）验证 JSON/stdin I/O、--stage flag、 optimize/extract 子命令、save/resume 端到端。

33.5 接口 vs 算法的分离

为什么 CLI/Python/JSON 在本篇 它们是接口包装（同一 FilterDesign 的三种暴露面），不含独立数学。 核心数学在第二～五篇。把接口混入数学章节会让"算法在哪实现"的追踪变模糊—— 故按任务要求分离。追踪"某算法在哪"：见附录 C 映射表。

33.7 本章小结

三接口：Rust（主，FilterDesign 全功能）、Python（pyo3 包装，逐位一致）、 CLI（JSON 4-stage 管道 + save/resume + 子命令）。接口不重复数学。 下一章可复现算例集汇总。
