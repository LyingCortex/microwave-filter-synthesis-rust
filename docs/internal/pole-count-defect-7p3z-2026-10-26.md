## 5. Python 引擎与 MFS 第一次出现实质差异的位置

- **多项式层面:无实质差异。** Python 引擎(fuqtgui `CouplingMatrix`)用同一组 Ω/RL 算出的 E/F/P 与 MFS 在 ~1e-13 内一致(eps、eps_r 相同)。
- **根层面:无实质差异。** Python 用 `np.roots` 对同一 yd 多项式求根:7 根,近对 `−1.58e-10+j1.136208189` / `+1.58e-10+j1.136213144`,**最小间距 4.9549e-06**,与 MFS 相同(到求解精度)。
- **第一次实质差异 = 极点合并决策,发生在"根 → 留数极点"这一步:**
  - MFS:`CLUSTER_TOLERANCE = 1e-5` 单链聚类(expansion.rs:221),4.95e-6 < 1e-5 → 合并 → 6 极点 → 拒绝。
  - Python:`scipy.signal.residue(y, yd, tol=1e-10)`(coupling_matrix.py:766-768,默认 tol=1e-10),4.95e-6 > 1e-10 → 保留 7 极点 → 成功构建 9×9 实矩阵(对角 1.1935/1.0952/0.5573/−0.1784/−0.8017/−1.136208/−1.136213,交叉 0.3086/0.4329/−0.4329 等,全部有限)。
- **重要警示:Python 引擎不是稳健的对照基准。** 实测把 scipy 的 tol 提到 1e-5(与 MFS 同档):`len(p11)` 仍 = 7(`residue()` 会把 multiplicity 重新广播回 p 数组),因此 Python 自己的计数检查 `len(p11) != order`(coupling_matrix.py:775)**在结构上永远不会触发**;但该次运行静默产出一个**含 NaN 的矩阵**(`sqrt(负留数)` → RuntimeWarning,矩阵含 NaN)。即:Python 在同等容差下是"静默产出坏矩阵",MFS 是"响亮拒绝"——两者是同一个底层问题(4.95e-6 的近重合对)下的不同失败模式。

## 6. 候选根因(含支持与反对证据)

### RC1(主因,证据强):`CLUSTER_TOLERANCE = 1e-5` 绝对阈值把两个数学上不同的极点合并了

expansion.rs:213-220 的注释给出 1e-5 的依据:"不同极点至少相隔 ~1.6e-3(order 16 实测)"。**该假设在本次配置下不成立**:order 7、这组 Ω 下,极点对在 s ≈ j·1.1362(恰好靠近传输零点 j·1.1362)处发生近重合,间距只有 4.95e-6,落在 1e-5 阈值之内。

支持证据(全部实测):
- 三独立求解器(faer/DK/Aberth)一致给出 7 根、间距 4.95e-6、残差 ≤ 8.3e-15——根是浮点分母多项式的真实根,不是求解器噪声;间距比残差大 9 个数量级。
- **z0 扫描**(固定 z1=2.3415、z2=−1.4132,z0 在 [1.1360, 1.1364] 扫描):失败窗口 = {间距 < 1e-5}。实测:z0=1.13617 通过(间距 1.81e-5);z0=1.13619 起失败(9.33e-6);z0=1.1362 失败(4.95e-6);z0=1.13621 失败(5.85e-7);z0=1.13623 失败(8.16e-6);z0=1.13624 通过(1.25e-5)。窗口中心 z0*≈1.136208(该处间距 ~3e-7),宽度 ~±2.5e-5,与"z0 偏移 1e-6 仍失败、1e-4 恢复"的观察一致。
- **RL 扫描**(同组 Ω):仅 RL=23 失败;21、22、22.5、23.5、24、25、30 全部通过;RL=1.5 时该对间距 1.14e-1(0.8777 vs 0.9919),远在窗口外。**见下方"未决项"。**
- "改带宽/Qu/无损条件仍报错"与本机制一致:带宽/Qu/损耗在归一化 s 面极点放置之后才参与去归一化,不改变归一化域内的极点间距(无损=eps_r=1 正是本复现条件,确实报错)。
- 间距随 (z0−z0*) 平滑(近似平方律)变化:z0*=1.136208 处 2.9e-7,记录值 1.1362(低 z0* 7e-6)处 4.95e-6——这是 Chebyshev 原型在该零点配置下的**真实数学性质**(极点近重合,类似"极点凝聚"),不是某个偶发数值 bug。

反对/局限证据:
- 注释中"≥1.6e-3 最小间距"是其他配置的实测,本次配置证伪了该假设的全局性——但这恰好就是 RC1 的成立条件。
- 单纯把阈值调小(如 1e-8)可修好本例,但对真正二重根输入(间距 ~1e-8…1e-15)无法区分"求解器拆开的真二重根"与"两个相距 1e-8 的简单极点"——这是该机制的固有张力,不是本例的直接反证。

### RC2(备选,已被证据否定):根求解器出错(漏根或把单根错拆/错并)

反对证据(强):三独立算法(faer 特征值、Durand-Kerner、Aberth)+ Python 的 `np.roots`(完全独立的伴随矩阵算法)全部一致返回 7 根、同一 4.95e-6 间距;残差 ≤ 8.3e-15。若真是二重根,教科书判别式行为会给出间距 ~1e-13…1e-10 量级,而非比求解器残差大 9 个数量级的 4.95e-6。"got 6"来自聚类而非求根(求根输出是 7)。**排除。**

### RC3(次要/贡献性,值得在修复阶段处理):合并极点的重数判定语义缺陷

合并后极点带 `laurent = Some(2)`:主部 b0 ≈ 1.32e-7(= (A−B)·d/2 量级,随间距 d→0 而消失),b1 ≈ 0.229(A+B),b0 高于 trim 阈值 max(1e-10·|b1|, 1e-14) ≈ 2.3e-11,故未截断。**这意味着:即使计数检查不触发,transversal.rs:34-42 也会以 `NotImplemented("transversal synthesis cannot represent a repeated pole")` 拒绝。** 真正能区分"两个不同极点"与"真二重根"的信号是 b0:不同极点 b0 ~ O(d) → 0,真二重根 b0 = O(1)。代码已经计算了主部,但只用它做 trim,从未用它决定重数——重数判定完全依赖间距。这是"为什么错误提示是数量不匹配而不是'重复极点'"的原因,也是修复方向的关键素材。

### RC4(完整性列出,已排除):分母首项相消/降阶

admittance.rs:40-107 的防护与 fallback 均针对首项相消。实测分母阶数 = 7、7 个根,无降阶。**排除。**

## 7. 下一步最小验证实验(区分力分析)

**E5(直接验证 RC1 为直接原因)——最小改动:仅把 `expansion.rs:221` 的 `CLUSTER_TOLERANCE` 从 1e-5 改为 1e-7,不动任何其他代码,重新构建并跑记录输入。**
- 预期:7 个极点、构建 9×9 矩阵,对角 −1.136208/−1.136213、交叉 ±0.2966/∓0.3758,与 Python tol=1e-10 的矩阵逐元素一致(差异应 < 1e-10)。
- 区分力:若通过 → 证实计数错误纯由阈值量级导致(RC1 确认,端到端)。若仍失败 → 阈值非根因,需回头查主部/trim 路径(指向 RC3)。它**不能**区分"调阈值"与"用 b0 判定重数"哪个是正确修复策略——那需要 E6。

**E6(区分修复策略:阈值 vs 重数判定)——在 z0 精细扫描逼近 z0*≈1.136208(间距 → 2.9e-7 甚至 < 1e-8)时观察 b0。**
- 预期:接近凝聚点处 b0 → O(d) → 0(两个不同极点),而真二重根处 b0 = O(1)。据此验证修复规则"仅当 |b0| > κ·|b1|(如 κ=1e-3)时按真二重根处理,否则保留为两个简单极点"在本例与真二重根输入上分别给出正确行为;同时暴露"单纯调低阈值"策略的死角(间距 < 新阈值的输入会被误判为真二重根 → NotImplemented 或坏矩阵)。
- 区分力:决定修复采用"更小的固定阈值"(治标,仍有未覆盖区域)还是"主部 b0 判定重数"(治本,语义正确)。

**已完成的判别实验**(第一轮内执行,供修复阶段引用):
- 三求解器交叉对比(区分 RC2):三算法一致 → 排除求解器。

## 8. 未决项(如实标注)

1. **"1.5 档" 的含义已由用户确认:温漂(温度漂移)档位,不是 RL。** 早期"1.5 档 ↔ RL=1.5"的猜测作废。记录零点在 RL=23 下精确复现全部症状(报错、位级确定、z0 窗口、1e-4 恢复),因此回归测试锚定"记录零点 + RL=23"。温漂维度本身:本修复处理的是归一化 s 面极点间距,温漂(频率/谐振频率随温度偏移)在去归一化之后进入,不改变归一化域内该对极点的 4.95e-6 间距——即温漂档位不会把该缺陷重新引入;若温漂需要端到端覆盖,应在去归一化/响应评估层面另设测试,超出本次最小修复范围,未做。
2. 用户"改 Qu 仍报错"的具体 Qu 值未知;本复现是无损(eps_r=1,与"使用无损条件仍报错"一致),有损变体因 F/eps_r 项会轻微移动极点间距,但 1e-5 窗口内的输入对这种微小移动不敏感——机制上自洽,未逐一重测。
3. 若输入更接近凝聚点(间距 < 1e-6),即使修复计数问题,transversal 拓扑本身无法表示真二重极点——`NotImplemented`(transversal.rs:34-42)在那种输入上是**语义正确**的,修复不应"顺手"消除它。

## 9. 结论

`expected 7, got 6` 的直接原因是 `expansion.rs:221` 的 `CLUSTER_TOLERANCE = 1e-5` 单链聚类把一对相距 4.95e-6 的真实不同极点(归一化 s 面 s≈j1.1362,该配置下 Chebyshev 原型的真实近重合)合并为一个二重极点;计数检查在 `transversal.rs:19` 首次以 6≠7 拒绝。Python 引擎"正常"仅因其 `scipy.residue(tol=1e-10)` 阈值更小,且其计数检查在结构上失效(同容差下静默产出 NaN 矩阵)。建议确认 RC1 后进入修复阶段,修复方向应为"用主部 b0 判定重数"而非单纯调低阈值(E5/E6 验证)。

### E6:求解器分辨率地板实测(已完成)

## 11. 最终修复:CLUSTER_TOLERANCE = 3e-7

**选定 3e-7 而非 b0 主部判据的理由:**

1. **锚定在实测的两条边界之间**:3e-7 = 2.2× 最大真二重根分裂(1.34e-7,deg-3),且 ≈ 1/16 的记录生产近对间距(4.95e-6)、≈ 1/5000 的旧注释"最小生产间距 1.6e-3",不会误并任何现有测试中的真实极点。求解器对真实不同根对的分辨能力实测到 ~3e-8 仍如实(见 §10 复测),因此 3e-7 不是"地板之上的必要值",而是"真重根分裂上限之上的安全余量"。
2. **b0 判据(E6 备选)被放弃,原因**:E6 实测显示,接近凝聚点时 b0 ~ O(d) 连续趋向 0,不存在 |b0| 的 O(1) 跳变(因为输入连续变化时,两个不同极点"变成"二重根是连续退化,不是离散事件)。任何 |b0| > κ·|b1| 判据在凝聚点附近同样落在一个狭窄区间内,等价于换了形式的间距阈值,且 κ 的选取缺乏同样的可测量依据。间距阈值 + 分辨率地板锚定是**唯一**能给出可验证数值依据的判据。
3. **真二重根语义保留**:间距 < 3e-7 的根对被合并为一个二重极点(laurent = Some(2)),transversal 路径仍按原有设计以 `NotImplemented` 拒绝真二重极点(transversal.rs:34-42)——未被绕过。

**代码变更**(`src/synthesis/residues/expansion.rs`):
- `CLUSTER_TOLERANCE: f64 = 1e-5` → `3e-7`,注释重写为分辨率地板依据(含 E6 实测数据)。
- 聚类循环、principal_part、trim 逻辑、transversal 全部不变。
